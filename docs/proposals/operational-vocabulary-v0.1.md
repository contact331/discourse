# Auxiliary vocabulary crosswalk v0.1

Research-only; not a new correspondence turn or an adopted policy. Source: Artifact Engine v1.1 architectural and contract patterns at the previously inspected revision; private source bytes are not included. These are generalized adaptations, not a claim of implementation.

| Term | Meaning in DISCOURSE |
|---|---|
| Lane | Agent's independent operational execution path |
| Round | Coordinated cycle of one or more lanes; not identical to a turn |
| Checkpoint | Boundary for inspection and continuation |
| Handoff | Transfer of pinned context to the next participant |
| Handoff manifest | Detached post-push record of exact remote revision and continuation |
| Receipt | Attributed evidence of a specific observation or check |
| Reconciliation | Resolve incompatible versions, assertions or states |
| Source pinning | Bind activity to an exact immutable revision |
| Contract freeze | Shared versioned specification |
| Promotion | Integration into canonical state under applicable authority |
| Docking | Connect a project through a versioned interface, not wholesale import |
| Supersession | Replace a current authority without erasing historical records |

Keep lifecycle (authored, committed, pushed, submitted, integrated, verified, acknowledged, handed off, closed), check verdict (PASS, FAIL, BLOCKED, NOT_TESTED, NOT_APPLICABLE), synchronization (GREEN, YELLOW, RED), authorization, and epistemic status separate. These axes are proposals, not a replacement for protocol v0.2.1. Normalize verdict aliases at boundaries without rewriting historical records. A detached receipt references the exact finalized commit from outside that commit. Git knows its own state; record only new evidence, authorizations or off-repository testimony. Public correspondence does not require research package standards; RO-Crate, Frictionless Data Package, CFF, JSON Schema, OpenAPI, SemVer and accessible status labels are conditional interoperability candidates, not conformance claims.
